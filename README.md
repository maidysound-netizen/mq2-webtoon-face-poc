# 웹툰 말풍선 배치용 얼굴 위치 교차 검증 PoC

웹툰 말풍선 배치 스크립트는 얼굴 좌표 파일(`faces.yaml`)을 보고 얼굴을 피해 말풍선을 놓습니다. 지금은 AI 오케스트레이션의 에이전트들이 그림을 보고 이 좌표를 적습니다. 이 PoC는 **내 컴퓨터에서 도는 만화 머리 탐지 모델**로 그 좌표를 대체하거나 검산할 수 있는지 확인했습니다. 지금 방식은 이미 빠르고(63컷에 30분 이내) 거의 정확해서, 관심사는 속도보다 **가끔 생기는 실수를 놓치지 않는 것**입니다.

- 문제 정의: [문제정의서.md](문제정의서.md)
- 시험 대상: 작가의 연재 원고 한 편(63컷, 그림은 공개하지 않음), 오케스트레이션이 적은 얼굴 78개
- 직접 돌려 보기: 원고는 공개하지 않으므로, 로컬에서 새로 만든 [30컷 샘플 에피소드](#샘플-에피소드-누구나-돌려-볼-수-있는-전체-파이프라인)로 전체 과정을 재현할 수 있습니다

## 결론

| 질문 | 답 |
|---|---|
| 로컬 모델이 오케스트레이션을 **대체**할 수 있나? | **아니다.** 머리 모델이 오케스트레이션 좌표의 94.9%와 일치했지만, 작가 기준(100%에 가까움)에 못 미친다. 지금 방식이 이긴다 |
| 로컬 모델로 오케스트레이션을 **검산**할 수 있나? | **그렇다.** 두 결과가 다른 컷만 보면 63컷 중 **5~8컷(8~13%)**만 확인하면 되고, 그 안에 오케스트레이션의 실제 실수(09a)가 들어 있다. 63컷에 약 7초 |
| 로컬 모델의 가치는? | 외부 전송이나 비용이 아니라 **틀리는 방식이 다르다는 것.** 언어 모델은 그림을 보고 좌표를 추정하고, 탐지 모델은 박스를 직접 잰다. 그래서 서로의 실수를 잡기 좋다 |

→ 판단: **오케스트레이션은 그대로 두고, 로컬 머리 모델을 검산 단계로 붙인다.**

강의에서 말한 "기준선이 이기면 그것도 결과다"에 해당합니다. 대체는 실패했지만, 그 이유(작가 기준이 높고 지금 방식이 이미 잘함)를 알고 나니 쓸 자리가 따로 보였습니다.

## 1단계: 대체할 수 있나 (단독 비교)

| 항목 | 처음 기준 | B. 얼굴 모델 | C. 머리 모델 |
|---|---|---|---|
| 오케스트레이션 얼굴을 찾은 비율 (임계값 0.1) | 90% 이상 | 87.2% (68/78) ❌ | 94.9% (74/78) ✅ |
| 오케스트레이션 얼굴 자리를 절반 이상 덮음 | 참고 | 35.9% | 78.2% |
| 처리 시간 (M1 Max CPU) | 컷당 1초 이하 | 0.11초 ✅ | 0.11초 ✅ |
| 라이선스 | 상업 사용 가능 | MIT ✅ | MIT ✅ |

처음에 정한 90% 기준으로는 머리 모델이 통과했습니다. 그런데 결과를 작가와 검토해 보니 **실제 기준은 100%에 가까웠습니다.** 오케스트레이션은 이미 거의 다 맞히고, 머리 모델은 그중 4개를 놓쳤습니다. 결과를 본 뒤 기준을 낮춰 통과로 적지 않고, **대체는 기준 미달**로 기록했습니다.

얼굴 모델(B)은 눈·입만 좁게 잡아서 말풍선이 피해야 할 머리 전체를 덮지 못했습니다. 그래서 2단계는 머리 모델(C)로 진행했습니다.

### 임계값

| 임계값 | 찾음률 | 오케스트레이션 좌표 밖 박스 |
|---|---|---|
| 0.01 | 96.2% | 123 |
| **0.1** | **94.9%** | **35** |
| 0.3 | 94.9% | 21 |
| 0.5 | 92.3% | 9 |
| 0.7 | 88.5% | 5 |

놓침이 더 아픈 실수(말풍선이 얼굴을 가림)라서, 찾음률이 떨어지기 전 가장 낮은 구간인 0.1을 골랐습니다.

## 2단계: 검산할 수 있나 (교차 검증)

```
오케스트레이션이 좌표 작성 (지금처럼)
        +
로컬 머리 모델이 따로 탐지 (7초, 다른 방식으로)
        ↓
두 결과가 다른 컷만 표시 → 그 컷만 작가가 확인
```

컷을 표시하는 경우는 두 가지입니다.
- **A.** 오케스트레이션이 적은 얼굴을 모델이 못 찾음 → 오케스트레이션 좌표가 어긋났거나 모델이 놓쳤다. 낮은 임계값(0.1)으로 본다
- **B.** 모델이 높은 점수로 찾은 머리가 오케스트레이션 좌표에 없음 → 오케스트레이션이 얼굴을 빠뜨렸을 수 있다. 엑스트라로 표시가 넘치지 않게 높은 임계값을 쓴다

| B 임계값 | 확인할 컷 | 비율 | 기준(15% 이하) |
|---|---|---|---|
| 0.5 | 8 / 63 | 12.7% | ✅ |
| 0.7 | 5 / 63 | 7.9% | ✅ |

### 표시된 컷을 그림으로 확인한 결과 (B 임계값 0.5)

| 컷 | 표시 이유 | 실제로는 | 누구의 실수 |
|---|---|---|---|
| **09a** | A: 주인공(char_B)을 못 찾음 + B: 배경 인물 머리 | 오케스트레이션 박스가 **얼굴 왼쪽 머리카락 위**에 어긋나 있음 | **오케스트레이션** ✅ 잡아냄 |
| **33** | B: 모델이 찾은 머리 | 배경에 **고개를 내민 강아지**. 오케스트레이션 좌표에 없음 | 오케스트레이션이 빠뜨림 (말풍선이 가릴 수 있음) |
| 35b, 37 | B: 모델이 찾은 머리 | 배경 군중 | 엑스트라. 피해도 되고 안 피해도 됨 |
| 09c | A: char_C 를 못 찾음 | 화염 속 괴물 얼굴 | 모델 (오케스트레이션이 맞음) |
| E1 | A: char_A·char_B 를 못 찾음 | 한 명은 **뒤돌아 있음**, 한 명은 작음 | 모델 (오케스트레이션이 맞음) |
| 17 | B: 모델이 찾은 머리 | 젓가락 든 **손**을 머리로 착각 | 모델의 헛경보 |
| 01 | B: 모델이 찾은 머리 | 가로등의 작은 점 | 모델의 헛경보 |

**오케스트레이션의 실제 실수(09a)가 확인할 컷 안에 들어 있습니다.** 모델이 놓치거나 헛경보를 낸 컷(09c, E1, 17, 01)은 작가가 한눈에 보고 넘기면 됩니다. 63컷을 다 보는 대신 8컷만 보면 됩니다.

## 기존 방식과 비교

| | 오케스트레이션만 (지금) | 오케스트레이션 + 로컬 검산 |
|---|---|---|
| 좌표 작성 | 에이전트가 그림 보고 추정 | 같음 |
| 실수를 발견하는 방법 | 완성 컷을 눈으로 검수 (63컷) | 표시된 컷만 확인 (5~8컷) |
| 추가 시간 | 없음 | 약 7초 + 확인 몇 분 |
| 검산 방식 | 없음 | 박스를 직접 재는 탐지 모델 (언어 모델과 틀리는 이유가 다름) |
| 63컷 좌표 작성 시간 | 30분 이내 (작가 기억, 정확한 기록 없음) | 같음 + 검산 약 7초 |

## 한계와 다음 단계

1. **기준선도 AI가 만든 것이다.** 기존 `faces.yaml`은 오케스트레이션이 적은 좌표라 완전한 정답이 아니다. 1단계의 94.9%는 정확도가 아니라 **일치율**이다. → 작가가 직접 확인한 정답을 컷 20개 정도 만들어 두 방식을 같은 정답으로 다시 채점
2. **한 편에서 알려진 실수가 하나뿐이다.** 09a 하나로 "실수를 잡는다"고 말하기엔 사례가 적다. → 다른 편에도 돌려서, 실제로 말풍선 가림이 났던 컷이 표시되는지 확인
3. **모델은 뒤통수, 괴물 얼굴, 손을 헷갈린다.** 이런 컷은 매번 표시될 것이다. 반복되는 헛경보는 표시 목록에서 기억해 두고 넘기는 방법을 검토
4. **배치까지는 안 돌렸다.** 표시된 컷을 고친 좌표로 `place_bubbles.py`를 돌려 말풍선 가림이 실제로 줄어드는지 확인하는 것이 다음 검증이다
5. **다른 언어 모델로 검산하는 것과는 비교하지 않았다.** 외부 전송과 비용은 이 업무에서 문제가 아니므로(문제정의서 6절), 다른 회사의 언어 모델로 한 번 더 적어 비교하는 방법도 후보다. 다만 같은 "보고 추정하기" 방식이라 같은 곳에서 같이 어긋날 수 있다는 것이 가설이고, 아직 재지 않았다 → 같은 편으로 두 검산 방식을 비교
6. **이름은 오케스트레이션이 붙인다.** 로컬 모델은 누가 누구인지 모른다. 검산 용도라 문제는 없지만, 대체하려면 캐릭터 구분이 따로 필요하다. 샘플에서는 대본의 인물 순서(왼쪽부터)로 이름을 붙였는데, 인물이 겹치거나 순서가 바뀐 그림에서는 틀린다
7. **말풍선 배치 규칙은 손대지 않았다.** 샘플의 가로 컷에서 두 사람의 말풍선이 엇갈려 놓였다(위 "샘플에서 본 것"). 말하는 사람 쪽에 붙이도록 벌점을 더해 봤지만 자리가 없어 결과가 그대로였고, 되돌렸다. 말풍선 크기를 줄이거나 두 말풍선을 함께 배치하는 방법이 다음 후보다
8. **샘플 그림은 로컬 생성이라 실제 원고 품질에 못 미친다.** 시연·재현용이다. 실제 작업의 그림 생성은 지금 쓰는 서비스를 그대로 쓴다

## 샘플 에피소드: 누구나 돌려 볼 수 있는 전체 파이프라인

위 측정은 실제 원고(공개하지 않음)로 했습니다. 저장소를 받은 사람도 처음부터 끝까지 돌려 볼 수 있게, **가상의 30컷 에피소드**를 로컬에서 새로 만들어 넣었습니다. 내용은 이 과제의 수업(내 업무 어디에 AI를 넣을까)을 가상의 학생 둘과 퍼실이 이야기하는 교육용 만화입니다.

![샘플 에피소드 세로 웹툰](samples/strip_ko.jpg)

```
대본 (story.yaml, Claude Code 가 씀)
  → ① 캐릭터 시트 4장   FLUX.2 klein 4B, 캐릭터마다 후보 3장 → 작가가 고름
  → ② 컷 30장          같은 모델, 컷에 나오는 인물의 시트를 참고 그림으로 넣음
  → ③ 머리 탐지        이 PoC 의 머리 모델 (30컷 3.2초)
  → ④ 이름 붙이기      대본의 인물 순서(왼쪽부터)대로 박스에 이름
  → ⑤ 말풍선 배치      얼굴을 피해서, 꼬리는 말하는 사람 쪽 (작가의 기존 웹툰 스크립트, 비공개)
  → ⑥ 세로 웹툰 조립
```

`bash run_samples.sh` 하나로 ①~④(생성은 mflux 가 있을 때만, 없으면 저장소에 든 그림을 씀)가 돕니다. ⑤⑥ 말풍선 배치와 조립은 작가의 기존 웹툰 스크립트로 돌렸는데, **저작권 문제로 저장소에 넣지 않았습니다.** 그 결과물이 위의 세로 웹툰(`samples/strip_ko.jpg`)입니다. 스크립트가 있는 사람은 `WEBTOON_DIR=<폴더> bash run_samples.sh` 로 끝까지 돌릴 수 있습니다. **모든 단계가 내 컴퓨터(M1 Max)에서 돌고 외부로 보내는 것이 없습니다.**

| 단계 | 도구 | 라이선스 | 걸린 시간 |
|---|---|---|---|
| 그림 생성 | [FLUX.2 klein 4B](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B) + [mflux](https://github.com/filipstrand/mflux) 0.24 | Apache 2.0 / MIT | 시트 12장 약 9분, 컷 30장 약 34분 (참고 그림 넣은 컷 1~3분, 배경 컷 30초) |
| 머리 탐지 | deepghs head_detect_v2.0_s + onnxruntime | MIT | 30컷 3.2초 |
| 말풍선·조립 | 작가의 기존 웹툰 스크립트 `place_bubbles.py`, `webtoon.py` | 작가 소유, **비공개** (저작권 문제로 저장소에 넣지 않음) | 몇 초 |

- 캐릭터 시트: `samples/characters/` (확정본) / `candidates/` (후보 12장) / `candidates_overview.jpg`
- 컷 생성 기록: `samples/generation_log.json` (컷마다 프롬프트, 참고한 시트, 시드, 걸린 시간)
- 다시 뽑은 컷: `samples/rejected/`. 04컷은 화이트보드에 BOTTLENECK 을 쓰게 했더니 두 번 모두 철자가 틀려서(BOTLENECK, BOTTLENEICOK) 글자 없는 장면으로 바꿨고, 24컷은 한 컷이 두 칸으로 쪼개져 나와서 다시 뽑았다
- 처음에는 Ollama 로 그리려 했으나, 설치된 Ollama(0.40)는 그림 생성 기능이 빠져 있어 mflux 로 바꿨다

### 샘플에서 본 것

- **머리 모델은 생성 그림에서도 잘 찾는다.** 대본에 적힌 인물 수보다 박스가 적은 컷이 하나도 없었다. 대신 배경의 엑스트라 학생 머리도 찾아서(2·3·8·14·19·22·25컷 등) 이름 없는 `extra` 로 남겼고, 말풍선은 그 얼굴도 피한다
- **28컷: 인물이 없는 컷인데 머리 18개.** 노트북 화면 속 만화 썸네일의 머리를 찾았다. 모델 입장에서는 틀린 게 아니다. "얼굴을 피하라"는 목적에는 오히려 맞다
- **말풍선은 얼굴을 가리지 않았다.** 다만 두 사람이 말하는 가로 컷(11·16·24)에서 말풍선이 **말하는 사람 반대편**에 놓이고 먼저 읽을 말풍선이 아래로 갔다. 가로 컷에서 말풍선(컷의 약 41%×36%)이 들어갈 자리가 얼굴 옆에 없어서다. 꼬리는 맞는 사람을 가리킨다. 얼굴 좌표 문제가 아니라 배치 규칙의 한계라서 이 PoC 범위 밖으로 두었다 (한계 7)
- **생성 모델은 글자에서 "오류 없이 틀린다".** 철자가 틀린 화이트보드, 읽을 수 없는 한자 같은 낙서(18컷). 강의에서 말한 것과 같은 종류의 실수다

## 실행 방법

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
bash download_models.sh

PANELS=<말풍선 없는 원본 컷 폴더>
FACES=<오케스트레이션이 적은 faces.yaml>   # 원고와 함께 비공개라 저장소에는 없음

# 1. 탐지 (점수는 반올림하지 않고 낮은 것까지 저장)
.venv/bin/python src/detect.py --panels $PANELS --model head_detect_v2.0_s
# 2. 임계값을 바꿔 가며 기존 좌표와 비교 (1단계)
.venv/bin/python src/evaluate.py --faces $FACES --model head_detect_v2.0_s
# 3. 교차 검증: 확인할 컷 목록 (2단계)
.venv/bin/python src/crosscheck.py --faces $FACES --model head_detect_v2.0_s --thr-a 0.1 --thr-b 0.5
# 4. 눈으로 검산 (초록: 기존 좌표, 빨강: 모델, 회색: 임계값 미만)
.venv/bin/python src/visualize.py --panels $PANELS --faces $FACES --model head_detect_v2.0_s --threshold 0.1
# 5. (참고) faces.yaml 과 같은 형식으로 자동 생성. 원본은 건드리지 않음
.venv/bin/python src/make_faces_yaml.py --model head_detect_v2.0_s --threshold 0.1
```

결과는 `results/<모델>/` 아래에 임계값별 파일로 저장되어 다시 돌려도 덮어쓰지 않습니다.

## 시연 자료

**결과 페이지: https://poc.veilnodehub.org/** (`docs/`)

- 실제 원고로 잰 수치와 교차 검증 표 (원고 그림은 싣지 않음)
